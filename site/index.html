Benchmarks from the C++ engine (Release build, one core). The gap widens as the network grows: Dijkstra's work grows with the area it floods, while contraction hierarchies stay at a few hundred nodes.

Why contraction hierarchies win

  1. Pay once, up front. Rank every intersection by importance, then "contract" them from least to most important, adding a shortcut whenever removing one would break a shortest path.
  2. Search upward only. A query runs from both ends but only climbs to more important nodes, so it touches a few hundred intersections instead of most of the map.
  3. Unpack the shortcuts. The route found is expanded back into real road segments, and it always matches Dijkstra's answer exactly.

Engineering

  • Compressed sparse row graph: a node's roads sit next to each other in memory.
  • O(1) "clear" between queries using round stamps, so each query costs what it visits.
  • 8 tests, every answer checked against Dijkstra, clean under AddressSanitizer and UBSan with GCC and Clang.
  • This replay comes from a trace hook in the engine that's off by default, so benchmarks aren't affected.
Code, tests and the full benchmark method are in the repository. The replay data is produced by haulroute_trace --grid 80.
